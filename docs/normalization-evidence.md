# 과거 KBO 경기 정규화 검증

2026-11-03. `apps/server/workers/normalize.py`는 종료 경기의 공개 문자중계와 별도 최종 득점을 입력받아 팀 관점 멘탈 지수에 필요한 사건 전 상황을 복원한다. **호출자가 일정 데이터에서 경기 종료 상태를 먼저 확인해야 한다.** 이 파서는 라이브 수집 완성이나 데이터 재배포 권한 확보를 의미하지 않는다.

## 입력·출력 계약

```python
normalize(html, away_team_id, home_team_id, away_runs, home_runs)
# NormalizationResult(events, complete, reason, source_counts)
```

- `events`: event_id, inning, half, outs_before, runners_before, margin_before, offense_team_id, defense_team_id, outcome, batter_name, source_kind.
- `margin_before`는 공격팀 득점에서 수비팀 득점을 뺀 값이다.
- event_id는 경기 내부 키(`inning:half:paN` 또는 `runnerN`)다. 다른 경기와 합칠 때 경기 ID로 이름공간을 구분한다.
- 주루 사건의 `batter_name`은 null이다. 이름은 화면 표시용이며 고유 선수 ID 또는 실책 책임 선수 식별이 아니다.
- `complete=false`의 events는 진단용 부분 결과다. 해당 경기의 점수·순위·요약을 게시하면 안 된다.
- `source_counts`는 원본 span 수, 처리한 반이닝 수, 정규화 사건 수 및 확인한 정정 판독 수다. span 수는 타석 수가 아니다.

## 확인한 원본 구조와 검증 규칙

반이닝 시작 문구가 각 역순 블록의 마지막에 있고, 같은 이닝에서 말 블록이 초보다 먼저 나타난다. 단순히 전체 배열을 뒤집지 않고 반이닝별로 재구성·정렬한다.

1. 첫 구간이 1회초인지, 반이닝이 빠지거나 중복되지 않았는지 확인한다.
2. 정상 경기 시작의 0:0·무사·주자 없음에서 시작한다. 반이닝 전환 때 아웃과 주자를 초기화한다.
3. 각 주자의 명시된 출발 베이스와 복원 상태를 대조한다. 진루·득점·아웃·대주자 교체를 반영하고 완료된 플레이의 베이스 충돌을 확인한다.
4. 병살은 타자 아웃과 명시된 주자 아웃을 합쳐 2아웃인지 확인한다. 마지막 포스아웃으로 이닝이 끝났을 때 기록되지 않은 나머지 주자의 진루를 임의 생성하지 않는다.
5. 안타 후 타자주자의 추가 진루, 명시된 주루 실책·폭투·포일·보크·도루를 구분한다. 같은 원인으로 여러 주자가 움직인 연속 줄은 한 사건으로 묶고, 도루 후 송구 실책처럼 원인이 다른 경우는 분리한다.
6. 안타·야수선택과 같은 플레이에서 파생된 별도 실책 등은 확인된 플레이 직전 상황을 사용한다. 타자주자 추가와 기존 주자 이동을 처리하는 중간 내부 상태(일시적으로 4명처럼 보일 수 있음)를 사건 전 상황으로 내보내지 않는다. 삼진 후 같은 투구에서 발생한 도루는 타자 아웃을 먼저 반영한 상황을 사용한다. 주루 사건을 타자에게 귀속하지 않는다.
7. 비디오 판독이 바뀌지 않은 경우만 기본적으로 통과시킨다. 판정이 바뀌었다면 이닝·초말·이름·현재 타석과 이미 기록된 최종 타자/주자 결과가 일치하는 제한된 유형만 통과시킨다. 타석 도중 체크스윙 정정은 판독의 투구 번호·타자·현재 타석과 직전 투구 종류(헛스윙/볼)를 대조한다. 도루·베이스 차단의 세이프 정정은 명시된 주자의 실제 도착 베이스와 일치해야 한다. 정정을 다시 적용하지 않으며 일치 증거가 없는 유형은 미완료 처리한다.
8. 각 반이닝의 3아웃을 확인한다. 9회 이후 홈 승리로 끝나는 마지막 반이닝은 예외로 처리하되 종료 상태와 최종 득점을 별도로 대조한다. 동점은 마지막 반이닝에 명시된 경기종료 문구, 모든 반이닝 3아웃, 별도 종료 일정 및 최종 득점이 필요하다. 연장 제한 이닝만으로 종료를 추정하지 않는다. 9회 미만 단축 경기는 제외한다.
9. 복원한 원정·홈 최종 득점이 입력된 최종 득점과 정확히 일치해야 complete가 된다. 알 수 없는 영향 사건을 건너뛰어 성공시키지 않는다.

지원 outcome: out, strikeout, double_play, hit, walk, home_run, error, fielders_choice, hit_by_pitch, sacrifice, wild_pitch, passed_ball, balk, stolen_base, caught_stealing. 고의4구와 자동 고의4구는 walk로 분류한다. 호수비·선수 책임·승리 기여도는 추정하지 않는다.

## 실제 소스 검증 결과

개발 중 임시 캐시로 실제 응답을 읽고 규칙을 대조했다. 원본 HTML·중계 문구·파생 선수 목록은 저장소에 추가하지 않았다. 아래는 기계적 상태/최종 득점 정합성 결과이며 공식 기록 전체와 수작업으로 대조한 보증이 아니다.

| 경기 ID | relay span | 반이닝 | 정규화 사건 | 최종 득점 원정:홈 | 결과 |
|---|---:|---:|---:|---|---|
| 20260901LGOB0 | 475 | 18 | 70 | 3:1 | 통과 |
| 20260901LTSS0 | 501 | 17 | 72 | 0:3 | 통과; 최종 타자 결과와 일치하는 정정 판독 확인 |
| 20260901HHKT0 | 549 | 17 | 76 | 1:6 | 통과 |

시즌 초 첫 10경기를 추가로 확인했으며 **10경기 모두 통과**했다. `20260328HTSK0`의 베이스 차단·타석 도중 체크스윙 정정도 명시된 진루·투구와 일치함을 확인했다. 추가로 `20260331OBSS0`(101사건), `20260331KTHH0`(100사건), `20260404NCHT0`(88사건), `20260405SKLT0`(89사건)도 통과했다. 번트안타, 파울 플라이 포구 실책, 이중도루 실패의 명시된 주자 아웃, 서로 다른 원인의 연속 진루를 구분하며 ABS 판정 방식 변경·헤드샷 퇴장처럼 확인된 행정 문구만 별도로 처리한다. 이 표본 비율을 시즌 전체 커버리지로 외삽하지 않는다. 전체 수집 후 실제 ready/incomplete/missing 집계를 별도로 보고해야 한다.

수집·수정 버전이 바뀌면 이미 계산된 지수를 같은 모델 버전·원본 해시 기준으로 재계산한다. 일부 소스나 파서가 실패하면 과거 성공 결과를 현재 결과인 것처럼 유지하지 않는다.

## 회귀 테스트

`tests/test_normalize.py`의 fixture는 가상의 이름과 직접 작성한 경기 상황이다. 실제 KBO 경기 복제본으로 주장하지 않는다.

```sh
cd apps/server
uv run pytest tests/test_normalize.py
uv run ruff check workers/normalize.py tests/test_normalize.py
```

28개 테스트가 역순 복원, 최종 득점 불일치, 누락 반이닝, 알 수 없는 사건, 아웃/주자 불일치, 병살, 3아웃 야수선택, 몸에 맞는 공·희생타, 타자주자 추가 진루, 복수 주자 폭투 중복 방지, 도루+실책 분리, 포일 득점, 정정 판독의 일치/불일치, 삼진 후 도루 상황, 만루 안타 후 실책의 중간 상태 배제를 검증한다. 추가 회귀는 타석 도중 정정 판독의 투구 번호/이름 불일치, 종료 문구가 있는 동점, 세이프 정정과 이중도루 실패, 번트안타와 파울 포구 실책을 검증한다. 실제 시즌 초 14경기의 전체 이벤트를 API의 NormalizedEvent 모델로도 검증했다.

## 남은 검증

- 지원하지 않는 판정 정정·특수 주루·종료 증거가 부족한 동점·단축·서스펜디드 경기 유형
- 원본 자체의 누락·수정 여부와 공식 기록의 독립 대조
- 시즌 전체 커버리지와 수집 재시도 운영
- 선수 ID 및 실제 책임 수비수 귀속
- 실시간 수집 지연·복구와 서비스 제공 조건

파서가 complete를 반환한 범위의 사건으로만 팀 관점 지수를 계산하며, 의학적 스트레스나 공식 야구 통계로 표시하지 않는다.

### 추가 보수적 지원과 제외 사례

`20260401LTNC0`는 82사건, `20260401WOSK0`는 93사건으로 최종 득점·반이닝·API 모델 검증을 통과했다. 명시적 우천 중단 문구는 상태 변경 없이 처리하고, 타자가 자신의 타구에 맞은 명시적 아웃을 지원한다. 파울→페어 정정은 같은 타자·타석·투구 번호의 타격 기록과 이미 기록된 안타/홈런이 일치하는 경우에만 허용한다.

반면 `20260401HTLG0`는 5회말 기존 3루주자의 득점/아웃/이동이 기록되지 않은 상태에서 2루주자의 3루 진루가 나타나 충돌한다. 최종 득점에 맞추어 누락된 사건을 만들어 넣지 않고 미완료로 유지한다. 해당 충돌 거부, 우천 중단과 타구맞음 아웃, 페어 정정의 투구 번호 불일치를 합성 회귀 테스트로 확인했다.

`20260331LTNC0`(85사건), `20260408KTLT0`(74사건), `20260331WOSK0`(85사건)도 추가 검증을 통과했다. 베이스를 맞고 굴절된 타구의 설명은 사건을 추가하지 않는다. 홈 태그 아웃 정정은 해당 타석에서 명시적으로 제거된 동일 3루주자와 일치해야 한다. 주자의 재치로 홈인한 기록은 진행 중인 확인된 타자 플레이에 붙은 경우만 허용하며, 타석 사이 원인 불명 득점은 허용하지 않는다. 이름 불일치와 타석 사이 득점 거부를 포함해 총 25개 합성 테스트가 통과했다.

### 독립 체크스윙·주루선 아웃 안내

`20260510HTLT0`(81사건), `20260515HHKT0`(81사건), `20260519LTHH0`(86사건), `20260524OBHH0`(76사건)을 추가로 검증했다. 독립된 체크스윙 안내는 이닝·초말·타자·현재 타석·투구 번호·정정된 투구 종류가 모두 맞아야 한다. 3피트 라인 아웃 안내는 동일 타자의 이미 기록된 아웃/희생타와 타격 투구 번호가 일치해야 하며 아웃을 추가하지 않는다. 1루 타구의 세이프 정정은 실제로 해당 타자가 1루에 존재해야 한다. 총 28개 합성 회귀 테스트와 실제 4경기의 API 이벤트 모델 검증이 통과했다.
