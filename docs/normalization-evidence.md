# 과거 KBO 경기 정규화 검증

2026-11-03 로컬 검증 기준. 종료 경기의 공개 문자중계와 별도 공식 일정의 최종 득점을 대조한다. 이 문서는 실시간 수집 완료나 운영 배포 완료를 뜻하지 않는다.

## 검증 범위와 저장 결과

정규시즌 종료 720경기·포스트시즌 종료 9경기를 조회했다. 시범경기 코드 `1`은 수집·저장·조회에서 제외한다. 총 729경기 중 **703경기의 양 팀 지수**, 정규화 사건 57,529건을 저장했다. 나머지 26경기는 검증 보류이며 지수와 부분 타임라인을 공개하지 않는다. 전체 목록과 분류는 [감사 스냅샷](data/2026-season-audit.json)에 있다.

초기 수집 후 파서 개선에는 저장소 밖의 비공개 임시 HTML 캐시를 사용했다. 캐시 재검증 중에는 네트워크 호출을 차단했다. Git과 DB에는 원문 중계를 저장하지 않으며, Git의 테스트 fixture는 가상 이름과 직접 작성한 상황이다. 실제 원문을 테스트 fixture로 복제하지 않는다.

## 정규화 계약

```python
normalize(html, away_team_id, home_team_id, away_runs, home_runs)
# NormalizationResult(events, complete, reason, source_counts)
```

호출자가 공식 일정의 종료 상태를 먼저 확인해야 한다. 이벤트는 이닝·공수·사건 전 아웃·주자 수·공격팀 기준 점수 차·양 팀·사건 종류·표시용 타자 이름을 포함한다. ID는 경기 내부 키이므로 여러 경기를 합칠 때 경기 ID로 구분한다. 이름은 선수 고유 ID나 책임 수비수 식별이 아니다.

`complete=false`의 이벤트는 진단용 부분 결과다. 저장하더라도 지수·순위·공개 타임라인에 사용하지 않는다. `source_counts`의 중계 줄 수는 타석 수가 아니다.

## 정합성 기준

1. 역순 반이닝 블록을 재구성하고 1회초부터 누락·중복 없이 이어지는지 확인한다.
2. 무사·주자 없음·0:0에서 시작하여 명시적 진루·득점·아웃·교체를 복원한다. 완료된 플레이의 베이스 충돌과 아웃 수 초과는 거부한다.
3. 병살·삼중살은 실제 타자와 주자 아웃 기록의 합을 검증한다. 타자가 살아남는 병살도 두 주자 아웃이 명시된 경우만 인정한다.
4. 같은 원인의 여러 주자 이동은 한 사건으로 묶고, 도루 뒤 송구 실책 등 서로 다른 원인은 구분한다. 타석 사이의 설명 없는 이동·득점은 추정하지 않는다.
5. 판독 정정은 이닝·공수·타석·선수·투구 번호와 명시된 최종 투구/타자/주자 결과를 대조한다. 이미 수정된 결과에 정정을 중복 적용하지 않는다. 주자별 같은 타석 내 이동 이력을 보존하며 선수명 충돌이나 확인할 수 없는 정정은 거부한다.
6. 안내 문구는 확인한 중단·경고·퇴장·교체 형식만 허용한다. 판정 설명은 해당 아웃·안타 등이 이미 기록됐는지 확인한 경우만 중복 안내로 처리한다. 알 수 없는 줄을 포괄적으로 무시하지 않는다.
7. 반이닝 3아웃과 마지막 반이닝의 종료 조건을 확인한다. 끝내기, 명시적 종료 문구가 있는 동점, 5회 이후 마지막 반이닝의 명시적 강우 콜드 선언을 별도로 검증한다. 우천 중단만으로 경기 종료를 추정하지 않는다. 종료 선언이 있어도 독립 최종 점수와 다르면 거부한다.
8. 복원한 양 팀 득점이 공식 일정의 최종 득점과 정확히 같아야 한다. 사건 ID 중복, 사건 전 아웃·주자 범위 위반도 거부한다.

## 사건 해석

- 낫아웃 포일·폭투 출루는 타자 아웃을 늘리지 않고 해당 회복 사건으로 기록한다. 다른 주자 수비 중 명시적 낫아웃 출루는 `strikeout_reached`로 구분한다. 공식 삼진 통계를 계산하는 모델은 아니다.
- 희생플라이 실책 출루와 도루 실패 중 실책 진루는 명시적 실책이 확인될 때만 아웃 없는 실책으로 처리한다.
- 무관심·재치·주루방해로 명시된 진루는 `runner_advance`이며 v1의 변화량은 0이다. 이를 공식 도루나 실책으로 간주하지 않는다.
- 파울 포구 실책은 타자·현재 타석·파울 투구가 일치해야 하며 아웃·출루·타석 종료를 임의 생성하지 않는다.
- 최종 지수·가중치·클리핑 규칙은 [시즌 명세](season-mental.md)에 있다. 호수비 질, 선수 책임, 승리 확률을 추정하지 않는다.

예를 들어 `20260401HTLG0`는 기존 3루주자의 이동 없이 다른 주자가 3루에 진입해 충돌한다. `20260614LTLG0`는 병살 표기 뒤에 두 번째 아웃이 없고 다른 주자가 실책으로 진루한다. 최종 득점에 맞추기 위해 누락된 아웃이나 이동을 만들어 넣지 않는다.

보류 기록은 독립된 공식 기록 또는 다른 검증 가능한 자료와 대조해야 한다. 자료를 확보하면 명시적 보정 근거와 테스트를 추가하고 해당 경기 양 팀 결과를 원자적으로 다시 계산한다. 현재 파서가 읽었다는 사실만으로 실제 경기 전체의 정확성을 보증하지 않는다.

## 회귀 검증

52개 정규화 테스트가 일반 타석, 주루·교체, 정정 판독, 동점·강우 종료, 중복·누락·불일치 거부를 검증한다. 전체 서버 테스트에는 저장소 원자성·일정 정정·시범경기 제외·수집 재개·캐시와 API 계약 검증도 포함한다.

```sh
cd apps/server
uv run pytest tests/test_normalize.py
TEST_MONGODB_URI=mongodb://localhost:27017 uv run pytest
uv run ruff check .
```

실제 로컬 DB에서는 모든 ready 경기의 양 팀 변화량이 서로 반대인지, 누적값과 타임라인이 일치하는지, 정규화 이벤트 모델이 유효한지 확인했다. 모바일은 실제 API로 목록·필터·관점 전환·미완료 상태를 확인했으며, 새 네이티브 배포 빌드와 운영 서버 연결은 별도 검증이 필요하다.
