# 출시 준비 실행 순서

2026-11-05 갱신. Render·Atlas 무료 운영 API와 최종 식별자의 양 플랫폼 스토어용 빌드까지 확인했다. **스토어 정식 출시 준비는 미완료**다. 기능 완성과 실제 스토어 제출·심사를 별도로 추적한다.

## 1단계 — 병렬 진행 가능한 기반 작업

| 작업 | 결과/진행 상태 | 다음 의존성 |
|---|---|---|
| 서버 설정 검증·배포 smoke 도구 | Render Free·Atlas Free에 배포하고 HTTPS API·DB 조회 확인 | 백업·복구·장애 알림 |
| 앱의 서버 조회 화면 | 운영 API 연결 및 iOS/Android 가상 기기의 시즌 조회 확인 | 개인 기록과 실제 경기 상태 연결 |
| 모바일 EAS production 빌드 자동화 | `mobile-release` 환경·토큰 연결, 최종 식별자의 iOS IPA·Android AAB 빌드 성공 | 스토어 앱 등록·업로드·실기기 검증 |
| 서버 이미지 배포 산출물 | `Publish server image` 추가: 동일 commit CI 성공 후 GHCR push, digest 기록 | workflow 실행 및 실제 런타임 연결 |
| 계정 준비 | Play 신규 개인 계정 생성 확인(소유자 확인). 인증 완료 여부 미확인 | 기기·본인 인증, 테스터 확보 |

서버 이미지 publication은 서비스 공개가 아니다. 런타임 배포에는 호스팅·리전·DB·비용·클라우드 인증이 추가로 필요하다. EAS production 설정 역시 서명 빌드 성공이나 스토어 등록을 의미하지 않는다.

다크 배경·Bagel 타이포·아이보리 CTA도 반영했다. 구장별 hero·응원석·팀 매핑은 미완료다.

## 2단계 — 데이터와 개인 기록 계약 (병렬)

- 데이터: 제공처 사용 조건, 자동 수집 주기, 선수/주자/아웃/점수 정규화, 중복·정정·재수집 검증.
- 개인 기록: 사용자 식별, 시청 시작 이후 이벤트 귀속, 접근 제어, 저장·삭제·기기 변경 정책.
- 디자인: 확정 테마·타이포 적용과 구장/응원석 매핑·이미지 권리 확인.
- 인프라: 호스팅 선택 후 비용 확인, staging DB·API, 비밀값·백업·오류 알림 준비.

이 단계의 계약이 확정되기 전, 과거 스코어 조회를 자동 스트레스 기록으로 표시하지 않는다. 구체 기준은 [서버 계획](backend-plan.md)을 따른다.

## 3단계 — 제품 기능 구현 (계약 이후 병렬)

1. 서버: 정규화 이벤트·개인 기록·선수/시즌 통계 API와 자동 수집 작업.
2. 모바일: 실제 경기 상태·시청 기록·응원팀·통계 화면 및 확정 디자인.
3. 알림: APNs/FCM 자격 증명, 일정 변경/취소·중복 발송 방지, 개인화 문구·구독 관리.
4. CI/CD: staging 실제 배포·동일 빌드 추적·실패 복구, Appium 네이티브 실행 job.

## 4단계 — 통합 검증

- 실제 API와 DB에 기록 후 앱 재실행, 접근 제어·삭제·정정 집계 검증.
- 양 플랫폼 Appium 핵심 시나리오, 실제 iPhone/Galaxy에서 원격 알림·링크 진입 검증.
- 수집 중단/오류/지연을 정상 경기 없음으로 표시하지 않는지 검증.
- 운영 서버 health·로그·백업 복구와 이전 앱 API 호환 확인.

## 5단계 — 플랫폼별 테스트 배포 (병렬)

- iOS: App Store Connect 앱·서명 확인 → store IPA → TestFlight → 실기기 확인.
- Android: Play 인증 완료 → AAB 최초 업로드 → internal 검증 → 신규 개인 계정 closed test(12명·연속 14일) → production access 신청.
- 공통: 실제 앱 스크린샷·개인정보·지원 URL·스토어 설명 준비. 콘셉트 이미지를 실제 화면으로 제출하지 않는다.

## 6단계 — 정식 공개

검증된 운영 서버 배포 → 스토어 심사 → 승인된 버전 공개. Android 비공개 테스트·production access·스토어 심사에는 외부 대기가 있다. 앱 기능 미완료 상태를 테스트 기간만 채워 출시 가능한 상태로 취급하지 않는다.

## 현재 사용자/외부 입력이 필요한 항목

- Apple/Play 앱 레코드, 푸시 인증 접근 및 실제 스토어 업로드 준비. Expo 배포 토큰·양 플랫폼 서명·최종 bundle/package는 설정했다.
- Play 본인·연락처·실제 Android 기기 인증 및 12명 테스터 모집.
- 데이터 사용 범위 확인과 실제 경기 수집 검증.

## AWS 비용 검토 결과

[AWS 비용 비교](aws-cost-comparison.md)를 추가했다. 기존 도서 서비스는 Lambda/DynamoDB 사용량 기반이므로 공유할 월정액 서버는 없다. 이 프로젝트의 최초 운영 API는 비용 없는 Render Free·Atlas Free로 배포했다. AWS 이전 여부는 용량·비용이 실제 문제가 될 때 다시 판단한다.

## 2026 시즌 공통 조회 구현

관전 여부와 무관한 과거 경기 조회를 별도 경로로 구현했다. 순서는 일정 수집 → 중계 정규화·검증 → 양 팀 지수 저장 → 공개 조회 API → 모바일 목록·상세다. 운영 API와 앱 조회는 검증했으며 모든 정규시즌 경기의 계산 완료는 별도 확인이 필요하다. [상세 명세](season-mental.md)를 따른다. 개인 관전 기록·선수별 통계는 아직 구현되지 않았다.
